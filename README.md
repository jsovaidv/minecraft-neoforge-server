## Java 21 还是 25？先看 Minecraft 版本

Java 版本不能凭“越新越好”选，NeoForge 和 Minecraft 版本对不上，服务端启动第一阶段就会报错。

| Minecraft 版本 | Java | NeoForge 版本线 | 备注 |
| --- | --- | --- | --- |
| 1.20.1 | Java 17 | NeoForge 47.1.x，和 Forge 47.1 同源 | 多数 Forge 1.20.1 模组能加载，但 NeoForge 1.20.1 的构建停在 47.1.106 |
| 1.21.1 | Java 21 | NeoForge 21.1.x | ATM10 在这个版本线，1.21.1 当时最新构建是 21.1.259 |
| 26.1 及更新 | Java 25 | NeoForge 26.x | 1.21.1 的整合包不要用 Java 25 |

ATM10 基于 Minecraft 1.21.1，所以 Java 21 是对的。它的 V7.0 服务端启动脚本指向 `neoforge/21.1.228/unix_args.txt`，说明整合包锁定的是 NeoForge 21.1.228。1.21.1 在 2026 年 10 月 12 日的最新构建是 21.1.259，但整合包没跟进之前，不要手动把 228 改成 259。整合包作者测试的是 228，你换成 259 出了问题，很难判断是模组冲突还是加载器版本不对。

升级 NeoForge 之前先备份世界。整合包更新时，优先用整合包自带的服务端文件，不要只换加载器。

## ATM10 要多少内存？10GB 和 12GB 差在哪

ATM10 整合包页面给的开服建议是 12GB 内存。在线人数多，或者建了大量机器、区块加载器，可以再加 2–4GB。雨云教程页面给的是 10GB 起步、4–6 核 CPU、10Mbps 带宽。两个说法不冲突：10GB 是起步线，12GB 更稳。

客户端和服务端的内存口径要分开看。客户端在启动器里分配 4–6GB 就够启动，但整机内存少于 16GB 可能不够用。雨云教程页面的说法是，客户端建议保留 10–12GB 空闲内存，推荐 32GB 整机内存。这个说法偏保守，但 500 个模组的客户端确实吃内存，浏览器、语音软件、录制软件都会抢。

服务端这边，12GB 是给 Java 的堆内存上限，不是整台机器只占 12GB。Java 自身、面板、系统都要留空间。给 Java 留 10–15% 的余量比较稳，不要把机器内存全部分配给游戏。雨云教程的启动命令用了 `-XX:MaxRAMPercentage=95.0`，在 10GB 机器上会逼近上限；如果面板和系统还要占内存，调到 80–85% 更稳妥。

带宽和内存是两回事。教程页面还给了一个估算：1Mbps 约带 2 人。50Mbps 对小型服很宽裕，但人数上限还受 CPU 单核性能、内存、模组数量和区块加载器影响，别只看带宽。

## NeoForge 服务端安装：空文件夹、Install server、EULA

NeoForge 服务端安装器有 GUI 和命令行两种用法。GUI 更直观，命令行适合面板服或远程服务器。

GUI 安装时，先建一个空文件夹，安装目录必须为空。打开安装器，选 **Install server**，勾选 **Server Starter Jar**，把安装目录指向那个空文件夹。安装完成后会生成 `run.bat` 或 `run.sh`。用命令行也可以，在空文件夹里执行：

bash
java -jar neoforge-<version>-installer.jar --installServer


把 `<version>` 换成你下载的安装器版本，比如 1.21.1 对应 `21.1.259` 的安装器。安装器会下载 Minecraft 服务端和 NeoForge 库。

内存写在 `user_jvm_args.txt` 里，不要直接改 `run.sh`。首次启动会因为 EULA 停下来，打开 `eula.txt`，把 `eula=false` 改成 `eula=true`，再启动一次。Linux 用 `./run.sh`，Windows 用 `run.bat`；想跳过服务端窗口，可以加 `nogui`。

更新 NeoForge 时，在同一个目录运行新安装器，它会替换旧版本需要替换的文件。更新前先备份世界。整合包更新比单独更新加载器更麻烦，先看整合包作者有没有说明。

## ATM10 面板服实操：上传、改端口、换启动脚本

雨云游戏云的 MCSM 面板服适合不想碰 Linux 命令行的读者。安装时环境选纯环境 / Java 21。进入面板后，先把服务端压缩包上传到文件管理，解压到当前目录。

解压后改两个地方。打开 `server.properties`，把 `server-port=25565` 里的 `25565` 改成面板端口映射给你的端口。面板显示映射到 48652，就改成 48652，以你实际看到的为准。然后打开启动脚本，文件名不要改，把内容清空，换成 ATM10 V7.0 的启动命令：

bash
java -Xms6G -XX:MaxRAMPercentage=95.0 @libraries/net/neoforged/neoforge/21.1.228/unix_args.txt


V5.5 对应 21.1.219，V6.6 对应 21.1.224，V7.0 对应 21.1.228。路径里的版本号要和整合包服务端文件夹里的实际路径一致，不要凭记忆改。

返回管理面板的终端页面，点启动。启动成功后，用面板给你的映射地址加入游戏。客户端整合包版本要和服务端一致，否则会被拒绝。

更新服务端时，先关旧服，保留 `world` 文件夹和这些文件：`server.properties`、`ops.json`、`whitelist.json`、`banned-ips.json`、`banned-players.json`、`usercache.json`、`usernamecache.json`、`server_banlist_config.json`。面板服的启动脚本也不要删。上传新服务端压缩包，解压，把启动脚本里的版本号改到新版本，再启动。

`server.properties` 里有几个值会影响体验：`max-players=20` 是人数上限，`view-distance=7` 是视距，`simulation-distance=5` 是模拟距离，`online-mode=true` 是正版验证，`white-list=true` 是白名单。这些是教程里的示例值，不是强制值。视距和模拟距离调高会明显吃 CPU 和内存，ATM10 这种 500 模组的包不要一开始就拉满。

## 本地开服 vs 面板服：什么时候别用自己电脑

本地开服能跑，但只在电脑开机时运行。关机、休眠、断网，服务器就断。朋友晚上想进，你的电脑就得一直开着。长期开服的电费、噪音和硬件损耗也要算进去。

外网加入还有网络门槛。同一台电脑用 `localhost` 就能进；局域网朋友要用你的局域网 IP；外网朋友要端口转发、防火墙放行 Java，还需要公网 IP。把公网 IP 发给别人，可能被扫描、DDoS，也会暴露大致地理位置。只给信任的人，别公开发。

面板服省掉的是硬件和网络维护。服务端在机房运行，不用你的电脑常开，不用自己做端口转发，换电脑也不影响。缺点是你要接受面板商家的配置和价格，不能像本地那样随意改系统。

选择规则可以很简单：只和朋友临时玩一两个晚上，电脑能一直开，本地就行；要 24 小时在线、多人长期玩、不想折腾端口转发，面板服更省事。ATM10 这种 500 模组的包，本地电脑至少 16GB 内存才比较从容，32GB 更舒服；服务端 12GB 更稳。

## 模组兼容与常见报错

NeoForge 不是“完全兼容 Forge”。1.20.2 及以上，Forge 模组不能跑在 NeoForge，NeoForge 模组也不能跑在 Forge；1.21 及以上会跳过 Forge jar 并给出警告。1.20.1 是例外：NeoForge 从 Forge 47.1 起步，mod ID 仍是 `forge`，多数 Forge 1.20.1 模组能加载。但 NeoForge 1.20.1 的构建停在 47.1.106，Forge 最新 1.20.1 构建是 47.4.26，要求更高 Forge 构建的模组不行。1.20.1 优先用整合包自带的加载器，通常是 Forge。

Fabric 模组要在 NeoForge 上跑，需要 Sinytra Connector，依赖 Forgified Fabric API，作者还推荐 Connector Extras。Connector 有 Forge 1.20.1、NeoForge 1.21.1、NeoForge 26.1.2 的构建，截至 2026 年 10 月都标 beta。服务端和客户端都要按模组所在的侧安装，别只装一边。

常见错误按出现频率排：

- **Java 版本错**：1.21.1 用 Java 17，或 26.1 用 Java 21，会报 `UnsupportedClassVersionError`。Cobblemon 1.7.3 和 1.8.x 只接受 Java 21，1.21.1 的 Cobblemon 服务器不能用 Java 25。
- **缺依赖**：Connector 缺 Forgified Fabric API，Cobblemon 缺 Kotlin for Forge，都会在启动时崩。
- **客户端模组放服务端**：报 `invalid dist DEDICATED_SERVER`，把仅客户端模组删掉。
- **Mixin 冲突**：两个模组改同一段代码，常见于手动加模组或更新模组后。
- **OOM**：`-Xmx` 太低，或者套餐内存太小。ATM10 用 10GB 启动、加机器后 OOM，就是内存不够。
- **EULA 未接受**：首次启动改 `eula.txt`。
- **端口占用**：报 `failed to bind port`，换端口或关掉占用端口的程序。

## FAQ：开服前最常问的几件事

**Java 21 够不够？**
1.21.1 和 ATM10 够。26.1 及更新要 Java 25，1.20.1 用 Java 17。别给 1.21.1 装 Java 25。

**ATM10 10GB 能开吗？**
能启动，但不宽裕。整合包页面建议 12GB，人多或机器多再加 2–4GB。客户端启动器分配 4–6GB，整机内存建议 16GB 以上，32GB 更舒服。

**本地开服，朋友怎么进？**
同一台电脑用 `localhost`。局域网朋友用你的局域网 IP。外网朋友要端口转发、防火墙放行 Java，还需要公网 IP。只给信任的人。

**更新会不会丢地图？**
按保留清单操作，先备份 `world` 和配置文件，通常不会。不备份就没有后悔药。面板服更新时不要删启动脚本。

**面板服要不要开正版验证？**
`online-mode=true` 是开启正版验证。关掉后离线账号能进，但必须配白名单，别公开地址。公开的离线服很容易被扫到。

**启动脚本为什么是 21.1.228，不是 21.1.259？**
ATM10 V7.0 锁定 21.1.228。1.21.1 当时最新构建是 21.1.259，但整合包没更新之前，不要盲目改。升加载器前先备份世界，并确认整合包作者已适配。
